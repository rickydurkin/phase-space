# P02 - First Principles: The Workshop

Programme v1.0.0. Prerequisite: P01 gate closed. Typical length: 4 to 6 sessions.

## Goal

Build the mission framework end to end and prove it with the first realm. This is the phase that turns a sandbox into a game: modes, objectives, stars, hints, debriefs, histograms, the necessity proofs, the tutorial, the Daily Experiment and the Phenomena Codex. Everything built here is reused by every later realm, so it must be general, data-driven and fully tested.

## What Ricky can do at the end

Boot the game, be playing within ten seconds, pass the tutorial, then work through twelve Workshop missions that each need a real piece of physics to earn three stars. Every morning there is a new Daily Experiment.

## Read first

- MASTER Part A; sections 4, 7, 8 and 9.
- MISSION-CATALOGUE.md: R1, the Daily Experiment templates for R1, and the codex seed list.
- LEARNINGS.md section 5 (mission formats that worked in Ricky's sims: Worldline, Orrery, Stability Triangle, Mach Cone).

## Plan (first session)

Write docs/phases/P02-plan.md and seed features.json. Order the work so one mission is playable end to end (Predict mode, R1-03 Galileo's Ramp) before the other modes are built.

## Work packages

### WP2.1 Mission schema and objective language

Zod schema for missions (MASTER 7.3) with a loader and clear validation errors. An objective DSL parsed once and evaluated in the AS every tick: zones, speeds, distances, contacts, angles, joint states, energy, time windows ("for 2 s", applying to the parenthesised expression before it, with parentheses required), sequences ("then"), counters, boolean logic with defined precedence, and derived per-attempt values (MASTER 7.3) such as maxSafeCargo. The evaluator is pure, deterministic and unit-tested, including property tests (random expressions against a reference interpreter).

### WP2.2 Modes and mission flow

All eight modes from MASTER 7.2. Briefing screen; planning phase (build or set parameters, with the allowed tools and budget visible); prediction entry where the mode needs it (a number with units, a multiple choice, or a sketch on a graph for later realms); attempt and run-cost handling; run; evaluation; debrief. Fresh numbers per attempt where the mission declares randomised parameters.

### WP2.3 Scoring, stars and histograms

Stars as MASTER 7.4. Metrics recorded per attempt. Local histograms for each metric, with reference distributions generated by bots and stored with the content. Personal bests are versioned by mission version and physics major version.

### WP2.4 Hints and debriefs

The five-level hint ladder with recorded use. The debrief generator: event timeline from the recorder, the governing equation with the player's numbers at Student depth (plain words at Explorer, the model card link at Physicist), prediction against result, the trap explained if the player fell into it, a real-world link with its source, and "branch and try".

### WP2.5 Necessity proofs

`npm run missions:verify` implements all ten checks in MASTER 7.6. Build the bot framework with every per-mode bot (uniform guess, random builder, prior-only answer, naive controller, naive design, random-scene detector test) and the adaptive bisection bot, all with seeded budgets. Traps are recorded as the reference with only the misconception's parameters changed. Results are cached by mission content hash and physicsVersion; push runs verify changed missions plus a sample, nightly runs verify everything. A reporter writes a table per mission into the gate report. The test API can record reference and trap replays from a session and run solver scripts for randomised missions (MASTER 7.1); the new-mission skill wraps both.

### WP2.6 The Workshop realm

The 3D Workshop environment (benches, racks, a ramp hall, a vacuum chamber, a zero-gravity bay, an outdoor yard for launches) and twelve missions, R1-01 to R1-12 from the catalogue. For each: the physics brief, expected numbers computed by script and kept in content/missions/R1/notes/, references and traps recorded, missions:verify green, and a mission-critic review.

### WP2.7 Onboarding

Boot into a live Workshop scene; grab, throw and stack within ten seconds; the first prompt after the first interaction; no failure for five minutes; three new ideas per step at most. The tutorial is itself a sequence of missions and passes checks 1, 2, 7 and 8 (it has no failure states, so the trap and guessing checks do not apply).

### WP2.8 Campaign map and progression

Realm map with stars, the R1 missions and locked silhouettes of later realms. Star thresholds open later realms (tune in playtest). Instruments are introduced with the mission that first needs them.

### WP2.9 Daily Experiment v1

The generator pipeline (template, candidate, solvability proof, necessity proof, accept) with three R1 templates from the catalogue. The UTC date is the seed. CI proves the next 400 days into a manifest that ships with the game (MASTER section 8). A plain-text share line and a PNG card. Fix the start date of the 30-day gate window in the phase plan.

### WP2.10 Phenomena Codex v1

Twenty mechanics entries from the codex seed list, each detected by its physical signature in any mode (for example, the Dzhanibekov entry checks for a flip of the intermediate axis while angular momentum is conserved). Entries have three depth levels, the equation, a real-world link with source and a challenge variant.

### WP2.11 Achievements v1

Insight-based: predictions within 5%, three-star without hints, first codex discoveries, first Daily streak of seven days.

## Benches

All earlier benches stay green. Add objective-language and evaluator tests, and bot-framework tests (a bot with a known success rate on a synthetic mission reports that rate within statistical tolerance).

## Missions and content

R1-01 to R1-12, three Daily templates (DT-R1-a to DT-R1-c), the tutorial sequence and twenty codex entries.

## Gate

- [ ] missions:verify passes every applicable check for every R1 mission and the tutorial, and for the 30 generated Daily Experiments starting on the date fixed in the plan; the 400-day manifest is built.
- [ ] Each R1 mission has a mission-critic review recorded, with every blocking point resolved.
- [ ] The qa-player subagent completes the tutorial and R1-01 to R1-04 with no help, through the UI.
- [ ] Debriefs show correct numbers for the player's own run (spot-checked against the recorder for three missions).
- [ ] Objective-language property tests pass.
- [ ] Time to first fun under 60 s in Ricky's playtest.
- [ ] The automated P00 and P01 gate items still pass (regression).
- [ ] Zero console errors across the E2E mission suite.

## Ricky's playtest (30 minutes)

1. Start the game cold and play the tutorial. Note the moment it first felt fun.
2. Play any six Workshop missions, trying for three stars without hints.
3. Deliberately try the "obvious" wrong approach on two missions and read the debrief.
4. Play today's Daily Experiment and share the result line.
5. Rate each mission you played: clarity (1 to 5), fun (1 to 5), "did it need real physics?" (yes or no).

## Out of scope

Other realms, generator templates for later realms, global leaderboards.

## Risks and mitigations

- Missions that can be brute-forced: add randomised inputs or reduce attempts until the bots fail, keeping bands at least twice the combined tolerance (check 9); never loosen a bot.
- Debrief text that feels generic: write templates per mission, generated numbers only fill the gaps.
- Tutorial fatigue: cut text; the first five minutes should be almost wordless.

## Stop and ask Ricky if

A mission he rates below 3 for fun cannot be fixed without changing its physics idea, or star thresholds for opening realms need his preference.
